# 工作流

## 固定的兩個循環

### 循環 A：素材進入內容庫存

1. 驗收來源包：定位、全文、上下文、完整度與公開邊界。
2. AI 從全部來源發現零到多個候選讀者問題。
3. JEV 判斷候選為 `ready`、`needs_context`、`needs_author` 或 `hold`。
4. AI 檢索相關庫存與已發布內容的短名單。
5. JEV 判斷 `distinct`、`update`、`merge`、`link_back`、`absorbed` 或 `needs_context`。
6. 批次更新內容庫存；不在發現每個候選時反覆改狀態。

### 循環 B：庫存形成生產配置

1. 讀取所有成熟、仍有時效或已達重啟條件的候選，不只看最新素材。
2. JEV 分別判斷週報單元、主題式長文、短札記三種非互斥格式準備度。
3. AI 綜合時效、內容差異、已在製作的稿件與產能，提出 `start`、`backlog`、`hold`。
4. JEV 複核遺漏、重複、跨篇依賴、來源／作者邊界與產能。
5. 作者或編輯只需確認一次整體配置。

格式準備度不是排程分數。候選可以適合多種格式，但每個成品必須服務不同且可獨立完成的讀者任務。

## 正式文章產製

1. **Assignment**：固定內容類型、讀者任務、來源範圍、公開邊界與完成條件。
2. **Brief**：建立主張、證據、限制、與既有內容差異；先跑 Brief Gate。
3. **Draft**：AI 依通過的 brief 寫完整可反應版本，不把素材堆疊當成文章。
4. **Truth**：事實、引句、因果、第一人稱及公開範圍。
5. **Depth**：承諾、來源容量、推理、內容路線價值與可遷移邊界。
6. **Experience**：入口、背景、導航、略讀路徑、術語負擔及讀者自主。
7. **Fidelity**：作者主體、立場、第一人稱、敏感內容及是否只是改寫舊文。
8. **Sepia**：套版、重複、節奏、段落與作者聲音。
9. **Final**：確切版本、前置 Receipt、交付包與內部資料外漏。
10. **Author approval**：作者接受確切版本後，才可能進入發布；發布本身仍是另一個動作。

每個 Gate 失敗時，AI 只改受影響區域，再以新內容重跑該 Gate。連續兩輪沒有可辨認改善就停止，不降低標準硬過。

## 為什麼不使用通用狀態機

這套流程是 prompt-first：Agent 依目前素材與稿件決定如何完成每一段，腳本只負責資料契約、JEV 呼叫、版本 identity 與 Receipt。一個笨重的 Runner 容易把寫作判斷誤當成固定機械步驟；完全自由的 Agent 又容易漏步驟或自評通過。這裡保留兩者各自擅長的部分。
