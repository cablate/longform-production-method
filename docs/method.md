# 方法總覽

這份文件讓第一次接觸的人理解整條方法。正式執行時，以 [`newsletter-production` Skill](../skills/newsletter-production/SKILL.md) 及其直接引用的 references 為準。

## 先分清楚兩個循環

### 循環一：素材成為內容庫存

輸入是有完整內容、上下文、來源定位與公開邊界的來源包；輸出是零到多個可追溯候選，而不是一個被迫選出的最高分題目。

1. 驗收來源包是否足以判斷。
2. AI 從全部來源發現候選讀者問題。
3. JEV 判斷候選是否成立，或還缺哪一類資料。
4. AI 找出相關庫存與已發布內容。
5. JEV 判斷候選應獨立、更新、合併、連回、視為已吸收，或回查上下文。
6. 批次更新庫存，保留來源與判斷 Receipt。

這個循環回答的是：「我們實際擁有哪些可發展內容？」

### 循環二：內容庫存成為生產配置

輸入是所有成熟、仍有時效或已達重啟條件的候選；輸出是一份可由作者一次確認的配置。

1. JEV 分別判斷週報單元、主題長文與短札記的非互斥準備度。
2. AI 綜合時效、差異、在製稿件與產能，提出 `start`、`backlog`、`hold`。
3. JEV 檢查遺漏、重複、跨篇依賴、來源邊界與過載。
4. 作者或責任編輯確認整體配置。

格式準備度不是排程分數。同一候選可以適合多種形式，但每份成品都要完成不同且可獨立理解的讀者任務。

## 正式文章怎麼產生

```text
Assignment
→ Brief → JEV Brief Gate
→ 完整初稿
→ Truth → Depth → Experience → Fidelity → Prose → Final
→ 作者核准
```

| 階段 | 產出或判斷 |
|---|---|
| Assignment | 內容類型、讀者任務、來源範圍、公開邊界、完成條件 |
| Brief | 主張、證據、限制與相對既有內容的新價值 |
| Draft | 一份完整、可供反應的候選稿 |
| Truth | 事實、引句、因果、第一人稱與公開安全 |
| Depth | 是否真正完成文章承諾與該內容路線的價值 |
| Experience | 新讀者能否進入、略讀、中斷後接回並保有選擇 |
| Fidelity | 作者主體、立場、聲音與敏感邊界是否保留 |
| Prose | 結構、重複、句群、段落節奏與發表場域是否自然 |
| Final | 前置 Receipt 是否綁定確切版本，交付包是否乾淨完整 |

每一關只處理自己的問題。失敗時，AI 定點修改受影響的位置，再以新版本重跑；不把好讀拿來抵銷事實錯誤，也不以自然語氣掩蓋內容空洞。

## AI、JEV 與作者的分工

- **AI**：理解來源、建立候選與 brief、寫完整稿、依 Receipt 定點修正。
- **JEV**：回答事先定義的有限判斷，保存輸入 identity、不確定性與結果。
- **作者／責任編輯**：決定立場、公開邊界、優先順序與是否接受確切版本。

JEV 不寫稿，AI 也不能用自評宣告正式 Gate 通過。全部 Gate 通過只代表可以交作者審閱，不代表核准、發布或寄送。
