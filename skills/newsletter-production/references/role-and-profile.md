# 電子報的作用與基本資料

電子報在每個事業中的作用不同。先弄清楚這一期要在作者與讀者的關係中完成什麼，再決定題目、深度、作者為什麼適合談這件事，以及讀者接下來可以做什麼。不要把某位創作者的銷售流程、出刊週期或內容類型套用到所有人身上。

## 開始前需要知道的基本資料

優先從使用者提供的素材、現有說明，或工作區中負責保存現況的文件取得資訊。只有缺少的答案會實質改變結果時才詢問，不要求使用者每次都重填一份品牌問卷。

| 欄位 | 必要性 | 決定什麼 |
|---|---|---|
| 本期讀者 | 必要 | 讀者原本知道多少、目前處境與理解這封信需要花多少力氣 |
| 這封信要幫讀者完成什麼 | 必要 | 要幫讀者理解、辨認、決定、嘗試、回應或採取什麼行動 |
| 來源與素材 | 必要 | 哪些內容可用、可確認，以及哪裡仍有缺口 |
| 內容任務 | 可由請求與專案判斷 | 編選、深入文章、通知或其他用途；決定來源範圍、編輯空間與完成條件 |
| 這期電子報的作用 | 可先推論；有多種可能時確認 | 維持關係、教學、整理外部內容、連結社群、呈現判斷或引導商業行動 |
| 作者／品牌和主題的關係 | 視內容而定 | 作者為什麼適合談這個主題或事件 |
| 哪些內容可以公開 | 有風險時必要 | 隱私、授權、內容歸屬、承諾、下一步行動與產品資訊 |
| 出刊與平台限制 | 選填 | 期間、篇幅、格式、預覽文字與交付方式 |
| 語氣／寫作風格指引 | 選填 | 編輯及後製時保留用詞與力道；不能取代作者的真實內容 |

## 電子報常見的作用

這些是選擇方向，不是互相排斥的產品類型。一期可以有一個主要作用和自然相容的次要作用，但不要讓多個目標一起爭奪篇幅。

- **關係維護：**固定抵達、分享近況或讓讀者理解作者正在處理什麼。
- **教學與實際使用：**幫讀者理解概念、完成判斷或嘗試一個方法。
- **呈現判斷：**讓讀者看見作者如何觀察、取捨、決定與承認限制。
- **案例／現場：**還原事件、做法、結果、限制，以及讀者可以如何用在自己的情況。
- **策展：**替讀者選擇、編排與解釋值得注意的外部內容。
- **社群連結：**反映共同問題、成員進展、對話與參與方式。
- **連到商業行動：**只有內容確實和產品、服務或活動有關時，才提供相符的下一步。

電子報不必是每位讀者都要經過的銷售步驟，也不必每期都銷售。它可能同時帶來關係、研究、教育或商業價值，但不能用一個數字證明所有結果。

## 寫作前先回答

寫作前至少能回答：

1. 這一期主要服務誰？
2. 他打開前處於什麼可觀察狀態？
3. 讀完後會得到什麼理解、更新、連結或選擇？編選可以讓讀者跟上多個話題，不一定改變立場。
4. 作者或品牌為什麼適合談這件事？根據是什麼？
5. 這一期不負責什麼？
6. 若有下一步，它是否自然接續這封信原本要做的事，而不是突然多出一個推銷目標？

如果電子報的作用、讀者或下一步行動只能由負責人決定，就提出一個具體問題。不要先假設每封電子報都要建立專家信任或導向購買。

資料可以由 AI 先整理成有理由的建議，不要求作者先把所有欄位填滿。多種內容並行時，分開內容節奏、單篇閱讀完整性與交付方式；共用名單或平台不代表內容必須有先後關係，也不自動建立新渠道。除使用者明確指定系列外，各篇應可單獨進入。實際寄送條件與次數依專案及授權決定。

## 系列與重複

電子報可以反覆處理少數重要主題。再次談同一主題時，至少要增加新的情境、證據、反例、用法、讀者問題或時間更新。若主張、材料與讀者用途都沒有改變，連回舊內容、縮成短訊或不寫，通常都比只換句話說更好。
