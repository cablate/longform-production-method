# 電子報生產

把真實素材整理成有根據、對讀者有用、可由負責人核准的電子報。保留作者原有表達；只有來源無法回答、且會改變內容的決定才交回作者。

## 先選任務模式

| 模式 | 做法 |
|---|---|
| 規劃 | 釐清電子報角色、讀者、素材、公開邊界與完成條件；不自行進入製作 |
| 完整製作 | 從素材與本期任務建立可反應稿，經必要 Gate 後交作者審閱 |
| 局部修改 | 只讀目前稿、相鄰上下文與受影響規則；不重跑整期流程 |
| 審查／回顧 | 檢查來源、結構、讀者體驗、作者原意或寄出後結果；不把審查自動變成改稿或寄送 |

再判斷內容是既有內容編選、深入文章，或其他通知／策展／社群型電子報。路線由讀者任務與新增論述的需要決定，不用字數或是否有新資料硬分。

## 取得最小必要上下文

先讀專案入口、目前有效稿件和 owning 文件。作者、讀者、素材位置、出刊作用、可公開範圍、語言與視覺偏好應來自使用者或專案 authority，不得套用某位作者的預設。

- 沒有會改變結果的背景缺口，就直接工作，不要求重填品牌問卷。
- 有舊 `production`、Gate Receipt 或 Runtime 狀態時，把它們當歷史證據；以目前稿件、來源與 `next_action` 判斷新版流程的起點，不延續舊節點控制。
- 對話中的 AI 是產製協調者；正文仍由單一稿件 owner 維護，JEV Receipt 另存並綁定確切版本。
- 若所在環境另有工作台或狀態機，本 Skill 只提供電子報內容方法與品質契約；外部控制面不得覆寫來源、稿件或 JEV Receipt 的 owner。
- 未採用節點 workflow 的專案照任務處理，不自動安裝流程。

### Prompt-first 與 JEV Gate

完整製作由主 AI 依本 Skill 分段執行，不依賴通用 Runner／Controller。YAML 或舊 workflow 只能作階段參考，不能取代目前來源、稿件與 JEV Receipt。

1. AI 負責取得完整原文、建立 brief、寫稿與回修；不同文章可並行，但每篇只有一份正式稿 owner。
2. 正式 Gate 全部交給 TypeSafe JEV；AI 不得用自評、fresh reviewer 或舊 Receipt 宣告通過。執行 Gate 或修改 Gate 契約時讀 [jev-gates.md](references/jev-gates.md)。
3. JEV 回傳有限 outcome 與所有原子問題答案。AI 依結果定點回修，修改後以新內容重新跑同一 Gate；連續兩輪無改善即停下，不降低 Gate。
4. fresh reviewer 只用於開發期校準、異常診斷或契約比較，不是正式產製節點，也不能覆蓋 JEV 結果。
5. 作者核准、寄送與成效仍是不同狀態；所有 JEV Gate 通過最多只能交作者審閱。

- 編選既有內容：加讀 [compilation-method.md](references/compilation-method.md)。
- 缺少電子報角色或作者基本資料：讀 [role-and-profile.md](references/role-and-profile.md)。
- 需要判斷內容類型、穩定價值、深度或完成條件：讀 [content-model.md](references/content-model.md)。
- 完整成稿、整期審稿或閱讀體驗／作者原意確實受影響：讀 [reader-and-author-fidelity.md](references/reader-and-author-fidelity.md)。
- 完整製作進入文字後製或使用者指定：依 [sepia-integration.md](references/sepia-integration.md)診斷；只有實質問題才局部修改。規劃與小幅修改標為不適用，不假裝跑過。
- 圖片確實在範圍內：正文主線穩定後讀 [visual-layer.md](references/visual-layer.md)。
- 修改本 Skill、workflow 或驗證方法：讀 [validation.md](references/validation.md)及受影響文件。
- 執行或調整正式品質 Gate：讀 [jev-gates.md](references/jev-gates.md)，使用 `scripts/newsletter_gate_jev.py`。

## 核心工作方式

1. 固定本期讀者任務、內容路線、來源範圍、公開邊界與完成條件。深入文章、既有內容編選、短札記、通知與策展各完成自己的讀者工作，不互相套版。
2. 建立來源可支持的本期任務、主張與理解路徑。判斷／案例型深文要能指出有依據的起點理解、更準確的問題、改變判斷的證據與可遷移邊界；編選則建立可獨立理解的內容單元，不強造單一 thesis。成篇前先確認同一讀者問題是否已有同一答案；共用來源不等於重複，但素材已被既有內容實質吸收、又沒有新增問題、證據或用途時，合併、縮短、連回或暫不成篇。選題與品質 Gate 都保存 JEV 的有限選項、原子問題答案、輸入版本與 Receipt；未完成案例集校準前，不把單一數值升成新的發布排序。資料足夠時直接寫出可反應版本，不用泛泛提問代替初稿。
3. 缺來源時先刪除、降格、縮小或局部改寫；只有不可替代的核心事實、作者立場或公開決定仍缺，才停下詢問。
4. 各階段由對應 JEV Gate 驗證；局部修改只重跑受影響 Gate 及其後必要 Gate。內容、來源或任務契約改變後，舊 Receipt 不得覆蓋新版本。
5. 直接交付目前任務需要的稿件與必要狀態，不附整套自評、行政表格或未要求的替代稿。

## 不可破壞的原則

- 分開來源事實、作者已表達內容、AI 推論與待確認缺口。
- 不捏造第一人稱經驗、情緒、判斷、客戶故事、研究結果、市場證明或作者聲音。
- 編選可以靠選材、排序與上下文產生價值，不必硬加新論點。
- 不把原始資料堆疊、加長貼文或內部摘要直接當成完成電子報。
- 讓新讀者能進入、中斷後能接回；簡潔不得削掉必要背景、推理、證據或限制。
- 長內容要有可辨認的略讀路徑；只看主旨、開頭、段落入口與結尾，也能知道本篇問題、主要推進與收穫。
- 不把故事、三點結論、固定字數、固定圖片數或行動呼籲設成每期必填。
- 不用假同理、恐懼、羞恥、身份威脅、虛假稀缺或不實承諾奪走讀者選擇權。
- 不公開私人對話、個資、未授權原話或合作內容。
- 未取得責任人對確切版本的核准，不寄送、不排程，也不建立外部承諾。

## 完成與停止

資料齊備可以零提問成稿。核心缺口未解決時，不得把含待決內容的版本標成 `review_ready`；`approved` 與 `sent` 必須分別有確切版本的作者接受與實際寄送證據。內容交接完成不代表平台、名單或寄送已驗證。

當本次要求的稿件或審查已成立、必要證據可回查、作者決定與外部動作仍在正確 owner，就停止；不要因 Skill 內存在完整 workflow 而自動擴張任務。
